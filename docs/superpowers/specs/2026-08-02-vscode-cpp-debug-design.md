# VS Code C++ 调试修复设计

## 背景

仓库中的 C++ 源码位于包含中文字符的目录。现有工具链是 GCC/GDB 8.1，实测 GDB 无法进入 `大二上\数据结构\leetcode练习`，因此 VS Code 在发送 `-environment-cd` 后终止调试。仓库当前的 `.vscode/tasks.json` 还存在乱码和 JSON 语法损坏，并且没有 `.vscode/launch.json`。

## 目标

- 在仓库内打开任意含 `main` 函数的 `.cpp` 文件后，按 `F5` 自动编译并进入调试。
- 支持仓库现有的中文目录，不要求移动源码或通过英文映射路径打开项目。
- 支持普通断点、单步执行、调用栈和局部变量查看。
- 保留全部现有源码和未提交改动。

## 非目标

- 不引入 CMake 或其他项目级构建系统。
- 不重构、格式化或修改现有 C++ 源码。
- 不为没有 `main` 函数的单独源文件推断链接依赖。

## 方案比较与决定

1. 安装 MSYS2 UCRT64 的新版 GCC/GDB：原生支持 VS Code C/C++ 扩展，配置简单，并可继续使用 GCC。采用此方案。
2. 改用 LLVM/LLDB：工具链较新，但 Windows 上的 VS Code 调试适配和配置更复杂。
3. 为仓库建立全英文路径映射并保留旧 GDB：无需安装，但每次都必须从映射路径打开仓库，使用成本较高。

## 实现设计

安装 MSYS2，并安装 UCRT64 GCC/GDB 工具链。VS Code 配置直接引用 `C:\msys64\ucrt64\bin\g++.exe` 和 `C:\msys64\ucrt64\bin\gdb.exe`，不依赖终端的 `PATH`。

修复或新增以下工作区配置：

- `.vscode/tasks.json`：使用 `-g -O0` 编译当前活动源文件，输出到源文件同目录下的同名 `.exe`。
- `.vscode/launch.json`：启动上述 `.exe`，以源文件目录作为工作目录，并通过 `preLaunchTask` 在每次调试前编译。
- `.vscode/c_cpp_properties.json`：让 IntelliSense 使用同一套 UCRT64 编译器和 C++17 标准。

数据流为：活动 `.cpp` 文件 → 预启动编译任务 → 同目录调试可执行文件 → 新版 GDB → VS Code 断点与变量界面。编译失败时，问题匹配器在 VS Code 中定位错误，调试器不会启动。若新版 GDB 仍不能处理该机器上的中文路径，则停止修改并使用英文目录映射作为后备方案。

## 验证与验收

1. 验证三个 JSON 配置文件均可解析。
2. 使用新编译器在中文目录内编译 `study.cpp`。
3. 使用新 GDB 在该目录执行 `cd`、载入可执行文件，并在 `main` 设置断点后启动程序。
4. 确认仓库原有源码改动未被修改或纳入提交。
5. 验收标准：在 `study.cpp` 中按 `F5` 后程序停在断点，能够单步执行并查看局部变量。
